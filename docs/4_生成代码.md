# 4. 生成代码:增量与幂等

如果即将要写入的文件不存在,就创建;已存在则必须经过 AST 解析后增量写入,不能直接覆盖。

## 写入引擎(internal/merge)

不用"整体重写文件",而是 `go/ast` 定位 + **文本拼接**:

1. `merge.Load` 解析现有文件,拿到每个声明的字节区间;
2. 生成器声明意图:`UpsertType` / `UpsertFunc` / `UpsertInterfaceMethod`;
3. `Render` 按位置从后往前切割拼接 —— 没被触碰的用户代码(注释、格式、空行)一字节不变;
4. 修补 import:补缺失的;只清理"原本有引用、合并后失去引用"的孤儿(用户自己没用的 import 不碰);
5. 结果必须仍能通过 `go/parser` 解析,否则报错拒绝写盘。

## 三种合并策略(Policy)

| 策略 | 行为 | 用于 |
| --- | --- | --- |
| `PolicyIfAbsent` | 已存在就跳过,签名不一致只告警 | logic(用户业务代码,绝不覆盖) |
| `PolicyIfSigDiff` | 签名变了才替换 | (保留,未来用于半托管层) |
| `PolicyAlways` | 内容不一致就整体替换 | api/vo 结构体、handler 胶水、路由函数 |

签名比较只看**参数/返回值类型**(不看参数名),所以改个参数名不会误判冲突。

## 幂等

- 内容比对:`format.Source` 规范化后比较,一致就不产生 op;
- 写盘:Render 无变化时不写文件(mtime 不变,git 干净);
- 顺序:接口按 yaml 声明顺序,结构体按登记顺序,不依赖 map 遍历。

## 增量语义约定

- yaml **新增**接口 → 所有层自动补齐;
- yaml **修改**接口签名 → 接口签名更新,handler/路由重写,logic 保留旧实现并打印告警;
- yaml **删除**接口 → 生成器不删用户代码,打印告警提醒手动清理;
- 用户在 service/logic/handler 里手写的其它内容 → 永不触碰。

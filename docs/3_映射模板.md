# 3. 映射到模板 / 生成代码结构

解析出的 `field.YamlList` 按 **domain**(yaml 文件名,接口级 `filename` 可覆盖)分组,
每个 domain 生成一组文件。所有命名由 `internal/handler/common.go` 统一约定:

| yaml(user.yaml,接口 CreateUser) | 生成物 |
| --- | --- |
| `req` | `internal/api/{domain}.go`:`{前缀}{接口名}Request`(+嵌套 `...Request{字段}Item`) |
| `res`(对象) | `internal/dal/vo/{domain}.go`:`{接口名}Vo`(+嵌套 `...Vo{字段}Item`) |
| `res`(单个基础类型字段) | 不生成结构体,service 直接返回该类型,如 `(int64, error)` |
| `res`(存在) | `internal/api/{domain}.go`:`type {接口名}Response response.BaseResponse[T]`(swagger 用) |
| 接口本身 | `internal/service/{domain}_service.go`:`I{Domain}Service` 接口方法 |
| | `internal/logic/{domain}_logic.go`:`{Domain}Service` 空实现(只返回零值,无 TODO 占位) |
| | `internal/handler/{domain}_handler.go`:`{Domain}Handler` 胶水方法(swagger 注解) |
| | `internal/router/{domain}_router.go`:`Register{Domain}Routes` |
| | `web/src/api/{domain}.ts`:`{Domain}Api` 类 + Req/Res interface |

注释的流转:yaml 中接口/字段的注释(行注释、上方注释)一路带到
Go 结构体注释、swagger `@Summary`、logic 方法文档注释、TS 的 jsdoc。

目标框架为 Gin(与 gen_review_resource 一致):handler 按请求形态用
`c.ShouldBindJSON / ShouldBindQuery / ShouldBind`(multipart),路径参数用
`c.Param` + strconv 显式解析,响应统一走 pkg/response 泛型封装;response 模型包以 res 别名导入。
